# 06 技术方案

> 状态：v0.2。目标平台：**只做网页版**，手机浏览器优先（竖屏），电脑浏览器居中显示同一竖屏画面。不开发 iOS / Android 原生应用。

## 1. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript（strict） | Codex 最熟 |
| 构建 | Vite | 快、配置少 |
| 界面 | React 18 + CSS（沿用 `02-界面规范.md` 的 token） | 卡牌游戏以界面为主，DOM 排版、文字、竖排都比画布方便 |
| 战斗表现 | PixiJS 8（只用于战斗场景） | 立绘移动、伤害数字、特效需要 60fps |
| 可安装网页 | PWA：清单文件 + Service Worker | 手机浏览器可"添加到主屏幕"、全屏运行、断网可玩 |
| 存档 | IndexedDB，并提供"导出 / 导入存档"；云端存档与账号 M2 之后再定 | 浏览器可能清除网站数据（清缓存、隐私模式、Safari 长期未访问），必须能手动备份 |
| 部署 | 静态网站托管（构建产物为纯静态文件） | 无需服务器即可上线 |
| 测试 | Vitest（逻辑）+ Playwright（界面冒烟） | — |

不选 Unity / Cocos 的原因：本项目界面占比高、战斗表现简单，网页技术更快。若日后要做原生应用或微信小游戏，战斗核心是纯 TypeScript，可以直接复用。

## 2. 架构

```
app/
  src/
    core/          # 纯 TypeScript，无 DOM、无 Pixi：战斗、数值、养成、存档结构
      rng.ts       # 确定性随机数
      battle/      # 战斗引擎（对应 tools/battle_sim.py）
      data/        # 由 CSV 生成的类型化数据
    ui/            # React 页面与组件
    scene/         # Pixi 战斗表现，只读取 core 输出的战斗日志
    platform/      # 存储（IndexedDB）、存档导入导出、页面生命周期、PWA 更新提示
  public/assets/   # 由 assets/characters 拷入的立绘 webp
tools/
  export_data.py   # data/*.csv → app/src/core/data/*.json + 类型
```

**关键原则**

1. **战斗是纯函数**：`runBattle(teamA, teamB, terrain, seed) → BattleLog`。界面只播放日志，不参与计算。这样战斗可以秒算（离线收益、扫荡），也能跑测试。
2. **数据只有一个来源**：`data/*.csv`。游戏不手写数值；`tools/export_data.py` 生成 JSON，构建时校验。
3. **Python 模拟器与 TypeScript 引擎必须一致**。两边改用同一个随机数算法（见第 3 节），用"金标准对局"做回归：同一输入、同一种子，两边的战斗日志逐行相同。

## 3. 确定性随机数

Python 与 TypeScript 都实现 **mulberry32**（32 位种子），不用 `random.Random` 或 `Math.random`。

```
function mulberry32(a) { return function() {
  a |= 0; a = a + 0x6D2B79F5 | 0;
  let t = Math.imul(a ^ a >>> 15, 1 | a);
  t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
  return ((t ^ t >>> 14) >>> 0) / 4294967296; } }
```

`tools/battle_sim.py` 同步改用此算法后，重跑 v2 主指标确认仍达标（随机数换了，数值会有小幅波动，属正常）。

## 4. 画面与适配

- 设计稿 1080 × 1920 竖屏，按宽度等比缩放；超长屏上下留宣纸底。
- 安全区用 `env(safe-area-inset-*)`。
- 电脑浏览器中居中显示一个手机比例的画面，两侧为宣纸纹理底。
- 手机浏览器横屏时提示"请竖屏游玩"，不另做横屏布局。
- 立绘使用 `card`（400×600）、`mini`（160×240）、`thumb`（96×144）三档 webp；详情页使用 `full.webp`（1024×1536，质量 85）。
- **网页包里不放 `full.png`。** `full.png` 是无损母版（每张约 3.8MB），只留在 `assets/characters/` 供后续加工；全员 56 人若都放 PNG，网页包会超过 200MB。
- **离线缓存分两层**：安装时只预缓存程序本体、字体、界面图和已解锁章节用到的 `card` / `mini` / `thumb`；`full.webp` 在玩家第一次打开人物详情时再下载并缓存。目标：首次安装下载量 ≤ 10MB。

## 5. 最小可玩版本（M1）范围

| 包含 | 不包含 |
|---|---|
| 阵营选择（太平 / 清） | 抽卡、商店、付费 |
| 编队：5 人 + 君主位，羁绊提示 | 装备、专属的养成界面（数据先接入，界面放到 M2） |
| 第一章 6 关（两阵营各一套，见 `07-关卡设计.md`） | 第二章以后的关卡 |
| 自动战斗播放：立绘、血条、怒气、伤害数字、技能名横幅、加速、跳过 | 复杂特效、音效 |
| 结算：胜利"捷"、失败"败"，史实战报一段 | 离线收益 |
| 开局赠送卡：每阵营 8 张（见 07 文档） | 升级、升星 |
| 本地存档：通关进度（IndexedDB） | 云存档 |

M1 验收：
1. `npm run dev` 网页可玩通第一章。
2. 金标准对局：100 组固定种子，TypeScript 与 Python 战斗日志完全一致。
3. 60fps：手机视口下战斗场景不掉帧（以 Chrome 性能面板 4× CPU 降速模拟）。
4. 界面元素符合 `02-界面规范.md`，与 `docs/界面样稿.html` 风格一致。

## 6. 上架前要注意的事

- 若面向中国大陆玩家，网页游戏同样需要取得版号；历史题材、真实历史人物和战争内容在审批中会被重点审查。是否面向大陆市场，建议在 M2 之前确定，它会影响内容与发行渠道。

## 7. M1.1（只做网页版后的补充工作）

1. 移除 Capacitor 依赖、`ios/`、`android/` 工程和相关脚本，确认类型检查、测试、生产构建仍通过。
2. 加入 PWA：清单文件（名称、图标、竖屏、宣纸色主题）、Service Worker 离线缓存；新版本上线时提示"有新版本，点击刷新"。
3. 存档导出 / 导入：导出为一个 JSON 文件，导入前校验版本与完整性；损坏的存档不覆盖现有进度。
4. 部署：产出可直接放上静态托管的构建目录，写明部署步骤；本地用 `npm run preview` 验证 PWA 安装与离线可玩。
