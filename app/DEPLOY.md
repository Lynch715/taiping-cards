# 太平天国 · 军报 网页静态部署

这是纯静态网页版，没有 Capacitor、原生工程或后端。手机竖屏优先，桌面居中显示同一游戏。

## 构建与交付目录

需要 Node.js 22+、npm、Python 3（数据导出脚本仅用标准库）。在项目根目录执行：

```sh
cd app
npm ci
npm run data
npm test
npm run package:static
```

构建前会校验 CSV 与生成 JSON。开放两条战役线各八章、共 96 关，前章通关后开放后章。玩家武将独立升级与升星，第1–4章保留既有配置，第5–8章使用固定目标到达日的12账号五人均级中位数校准；战斗读取实际等级、星级、普通兵装与4★专属。

同时生成版本压缩包 `release/taiping-web-0.4.4.zip`。可直接上传的目录是 `release/taiping-web/`，`app/dist/` 与之逐文件一致。**上传目录里面的全部文件和子目录**，包括 `index.html`、`manifest.webmanifest`、`sw.js`、`icons/`、`fonts/`、`assets/`。不要只上传 HTML，也不要上传 node_modules、CSV 原表或美术原图目录。

部署地址可以是域名根目录，也可以是 `/taiping/` 等子目录。清单、SW、静态素材使用相对地址；静态托管的目录 URL 应带末尾 `/`。不需要服务端路由重写。HTTPS 是线上 Service Worker 与安装的前提；本地 localhost / 127.0.0.1 可测试。

## 静态托管步骤

1. 选用支持 HTTPS 的静态托管，将 `release/taiping-web/` 的内容整体上传至同一目录。
2. 确认该目录访问 `/index.html`、`/sw.js`、`/manifest.webmanifest`、`/icons/icon-192.png` 返回对应文件，而非 404 或兜底 HTML。
3. `sw.js`、`index.html`、`manifest.webmanifest`、`pwa-build.json` 建议 `Cache-Control: no-cache`；Vite 哈希文件 `assets/*-HASH.js/css` 可设 `public, max-age=31536000, immutable`。人物素材 URL 没有文件名哈希，不要给它们永久不可变的 HTTP 缓存头。
4. 上线新版本时先传素材，最后更新 HTML 和 SW；优先使用托管方的原子目录发布。保留上一版素材至少到旧页面刷新完毕，避免旧页的延迟模块 404。
5. 浏览器首次打开后，等待“离线包就绪”。安装只缓存程序、字体、界面图和已解锁章节的 card / mini / thumb；首次下载量不超过 10MB。full.webp 首次查看时按需下载并缓存，不进入首次预缓存。兵装64px只预缓存一张雪碧图，128px详情图也按需获取，离线或加载失败回退64px。未缓存的大图断网时显示 card 预览。后续章节首次解锁需联网备齐素材，离线包就绪后可断网重开。
6. 用另一轮构建替换后，打开页面或点“军册备份 → 检查更新”，应出现“有新版本，点击刷新”。新包完整下载后才提示；战斗中不允许刷新。刷新前等待军册写入，不清除 IndexedDB。

## 本地安装与离线验收

```sh
cd app
npm run preview
```

打开 http://127.0.0.1:5192/ 。`npm run dev` 用于开发，不注册 Service Worker；验收离线必须用生产预览。

- Chrome / Edge 桌面版：地址栏安装图标或菜单“安装应用”。安装后确认在独立应用窗口运行，而非普通书签/快捷方式。
- iPhone / iPad Safari：分享 → 添加到主屏幕；应在实际设备上另验。桌面截图不代表已完成手机真机安装验收。
- 等离线包就绪后，在 Chrome DevTools 的 Network 中选择 Offline，重新加载，再进入两条战役、打开人物详情、出征至结算。验收后恢复 No throttling。
- 应用界面显示“离线”时说明浏览器已切到离线；Service Worker 从缓存提供资源。首次未缓存就断网无法启动，网站数据被浏览器清除后需要重新联网准备。

## 军册与备份

所有非战斗页面上方有“军册备份”。导出下载一个 JSON 文件，包含两个阵营的进度、编队、战斗种子、格式版本与 SHA-256 完整性校验。该校验用于发现损坏，不是防作弊或账号签名。

导入先校验大小（5MB 内）、JSON、版本、所有上阵人物与连续通关进度、完整性校验，再展示摘要；点“导入并替换军册”才写入。损坏文件不会覆盖进度；替换时把上一份有效军册与新军册放在同一 IndexedDB 事务中提交。支持原有 M1 的 IndexedDB 库与键名，不强制清档。

成长、资源、每人将魂、每件装备的强化与归属、招募保底、随机数状态、每日扫荡次数均随军册导出。导出格式版本仍为1，新增 growth.schema=1。旧 M1 / M1.1 / 0.2.0 军册首次迁移保留进度与编队，并按已通关位置补入等级和首通军需；放置从迁移时刻开始，不追溯。迁移在导入的首次原子写入前完成，旧军册备份不会被紧随的自动保存覆盖。

军册按浏览器、用户资料与站点 origin 保存。更换域名/端口或清理网站数据前先导出备份；跨设备用导入恢复。`?qa=英文标签` 为独立测试军册，验收不触碰默认军册。

## 养成验收

- 领取军需上限十二小时；时钟回拨收益为零。每关扫荡每日三次，两阵营合计每日最多30次，按本地零点重置；旧军册超额计数保留至次日。
- 招募、获得新武将会补齐对应缩图缓存；断网时新取得但尚未缓存的画像用剪影代替，战斗仍可播放。
- 全部96关敌级限定于该关假设玩家均级的−5至+10，敌军星级不超过6、等级不超过100；关卡数据记录具体星级。玩家星级等级上限沿用养成表。
- UI 测试军册只导入带 qa 参数的测试地址；不要覆盖正常军册。

## 回滚

回滚前先导出当前军册。旧版不支持养成、新招募编队与后期关卡，保留成长进度应恢复到支持 growth.schema=1 的版本。

将上一份完整静态部署目录重新发布，并保留当前素材至旧页面完成刷新。版本由内容哈希生成，内容回滚也会成为一次可提示更新。Service Worker 只整理游戏缓存，不删除 IndexedDB；旧缓存等同一作用域的所有打开页面确认新 HTML 后再清理。

智能布阵在独立Web Worker中试算，构建产生的worker哈希脚本属于程序预缓存；离线包就绪后断网仍可使用。试算20组候选各20局，保留君主并免费转移既有兵装，不强化、不分解、不消耗军功或随机数。推荐不保证实战胜利。

v0.4.2校准假设覆盖表`stage_level_overrides.csv`与关卡JSON随包提供；它不会给已有军册补等级、改收益或重置扫荡计数。银两大量结余保持为已知问题。


## v0.4.2 正式收尾

采用保守原价犒军：每日1次，两阵营共用；每次章节×8,000银两换章节×1,000军功。三倍单价未满足切价条件，生产表保持原价。96关、48关假设曲线和原产出均冻结，旧军册资源、进度与计数不重置。

最终经济验收是16项章节上限/等待＋2项主线中位总天数下限，结果与对照见项目根目录`assets/reports/economy_report_v042_final.md`。早先带章节耗时下限的报告是历史试验，不作为本版验收结论。

## v0.4.3 交付与真机清单

本版=已冻结v0.4.2经济＋用户已验收A/B/C批美术。地形为Q75；敌方卡框保留32px顶边距；不重置军册。`release/taiping-web-0.4.2.zip`留作旧包。

静态包内附`mobile-checklist-v0.4.4.html`。部署后从“游戏目录URL/mobile-checklist-v0.4.4.html”打开；真机逐项勾选，记录首装、离线重开、四地形、布阵秒数、兵装64与详情按需下载。清单勾选仅保存在该浏览器，另用“导出实测记录”留档；不会写游戏军册。首次首装计量先打开游戏，等“离线包就绪”再打开清单，避免把单独访问清单的流量混入该轮记录。

本地可用`python3 -m http.server 5194 --bind 127.0.0.1 --directory release/taiping-web`预览；手机须使用已部署的HTTPS地址（手机上的127.0.0.1指向手机本身）。本轮只交静态包，没有上线部署；真机项目全部留待使用者勾选。
